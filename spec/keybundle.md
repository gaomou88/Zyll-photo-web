# 密钥包规范 `zyll-keybundle.json`（v1）

密钥包放在网盘库根目录。它本身是明文 JSON，但里面只有被加密的主密钥（MK）。
新设备或网页端拉取该文件，输入密码（或恢复密钥）即可在本地还原 MK。

## 1. 格式

```json
{
  "format": "zyll-keybundle",
  "version": 1,
  "vaultId": "0f8c2c7e-4a1b-4d0e-9a51-2f3b8f6a9c11",
  "slots": [
    {
      "type": "password",
      "kdf": { "alg": "argon2id", "v": 19, "m": 65536, "t": 3, "p": 1, "salt": "<base64 16B>" },
      "nonce": "<base64 12B>",
      "wrappedMk": "<base64 48B>"
    },
    {
      "type": "recovery",
      "kdf": { "alg": "hkdf-sha256", "salt": "<base64 16B>" },
      "nonce": "<base64 12B>",
      "wrappedMk": "<base64 48B>"
    }
  ]
}
```

- base64 为标准字母表、带 `=` 填充。
- `m` 单位为 KiB。默认 `m=65536（64 MiB）, t=3, p=1`；解析时接受 `8192 ≤ m ≤ 1048576（1 GiB）、1 ≤ t ≤ 10、p = 1`，超出范围的密钥包一律拒绝（防止被改过的密钥包让解锁时内存耗尽）。
- 未知字段必须忽略；未知 `type` 的槽位必须跳过。

## 2. 派生与包裹

| 槽位 | KEK 派生 |
| --- | --- |
| password | `Argon2id(password = UTF-8(NFC(密码)), salt, m, t, p, 输出 32 字节)` |
| recovery | `HKDF-SHA256(ikm = 恢复密钥 32 字节, salt, info = "zyll/v1/recovery-kek", 32 字节)` |

`wrappedMk = AES-256-GCM(KEK, nonce, MK, AAD)`，其中

```
AAD = UTF-8("zyll-keybundle/v1|" + vaultId + "|" + type)
```

GCM 校验失败即“密码（或恢复密钥）错误”。

## 3. 恢复密钥

- 32 字节随机数，以 RFC 4648 Base32（大写、无填充）显示，共 52 个字符，每 4 个字符一组用 `-` 分隔。
- 输入时忽略空格、`-` 和大小写。

## 4. 修改密码、换恢复密钥

两样都只是用新的密码或恢复密钥把同一把 MK 重新包一次，MK 不变，所有已上传数据无需重新加密。

- **修改密码**：先用现在的密码或恢复密钥解开 MK（忘了密码也能改），再只重写 `password` 槽位（新 salt、新 nonce）。
- **换恢复密钥**：用现在的密码解开 MK，生成新的 32 字节恢复密钥，只重写 `recovery` 槽位（新 salt、新 nonce）。
- 其余槽位原样保留；写回时 `rev` 变大、重新计算 `mac`（见第 5 节），然后写进本机和每个放着这套密钥包的账号。
- 改之前先重新读一遍**每个**已登录账号里的密钥包，有一个读不到就不改（提示联网或重新连接），
  免得悄悄盖掉别的设备刚改的那份。读到更新、`mac` 也对得上的先换上，再用它解开；新的 `rev` 比读到的每一份都大。
- 写不进去的账号（断网、要重新连接）要在界面上说明“那里仍然是旧的密码和恢复密钥”，并在联网后自动补传，
  不依赖自动备份开着。
- 旧的密码或恢复密钥随即失效。注意：MK 本身没有换，网盘的历史版本或回收站里如果还留着旧的密钥包，
  拿到旧密钥包和旧密码（或旧恢复密钥）的人仍然能解开。怀疑密钥泄露时应该另建一套密钥、把照片全部换过去。

## 5. rev 与 mac

同一套密钥（同一个 vaultId）的密钥包会被改写，各设备要能分出哪份更新、是不是自己人写的：

```json
{ "...": "...", "rev": 1762800000000, "mac": "<base64 32B>" }
```

- `rev`：整数，毫秒时间，每次改写取 `max(现在, max(旧 rev, 见过的最大 rev) + 1)`。没有这个字段的旧密钥包按 0 算。
- `mac = HMAC-SHA256(K_mac, macInput)`，`K_mac = HKDF-SHA256(ikm = K_wrap, salt = 空, info = "zyll/v1/keybundle-mac", 32 字节)`。
  只有解开过这套密钥的设备才算得出来，网盘服务商改不了。
- `macInput` 是下面这些 UTF-8 文本逐项加换行（`\n`）拼起来：
  `"zyll-keybundle-mac/v1"`、vaultId、rev（十进制）；然后对每个槽位按顺序依次是
  type、kdf.alg、kdf.v、kdf.m、kdf.t、kdf.p（没有的写空串）、kdf.salt、nonce、wrappedMk。
  向量见 `test-vectors/keybundle-mac.json`。
- 设备看到网盘上同一套密钥、`rev` 比本机大、`mac` 也对得上的密钥包时，换上它（别的设备改过密码或换过恢复密钥），并提醒用户；
  本机的 `rev` 更大时把本机的写上去；一样大时不动。
- 网盘上那份 `rev` 更大、`mac` 却对不上（不是有这套密钥的设备写的，或者写坏了）：不可信，用本机这份覆盖。
- 换上别的设备写的密钥包时，逐个比较槽位：只有 `recovery` 槽位变了，本机还没让用户抄下的那个恢复密钥才作废；
  只改了密码时它照样有效，继续显示。提醒也分“密码改过”“恢复密钥换过”。
- 网页版不保留 K_wrap 的原始字节：解锁时从 MK 一并派生一把只能验证的 HMAC 密钥（不可导出）用来核对 `mac`。
- 新建密钥包时也带上 `rev` 和 `mac`。不认识这两个字段的旧版本照常能解锁（未知字段忽略）。
