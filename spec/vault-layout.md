# 网盘目录布局（v2）

Android 端现在用的布局。旧版 v1（用户可见的 `Zyll Vault/` 文件夹、HEAD 指针、操作日志）从未上线，已废弃。

```
<应用数据区>                          # Google Drive：appDataFolder（用户在网盘里看不到，也删不到）
                                      # OneDrive：/drive/special/approot
└─ Zyll 相册/                          # CloudConfig.ROOT_FOLDER
   ├─ index.json                      # 不加密时的备份目录（明文 JSON）
   ├─ <相簿名>/<文件名>                # 不加密时的原图，按相簿分文件夹
   ├─ .thumbs/<24 位随机十六进制>.jpg   # 不加密时的网盘缩略图
   └─ vault/                          # CloudConfig.ENCRYPTED_FOLDER，开了端到端加密后用
      ├─ keybundle.json               # 密钥包，见 keybundle.md
      ├─ index.zylc                   # kind=3，加密的备份目录
      ├─ ai-results.zylc              # kind=5，加密的 AI 整理结果
      ├─ <32 位随机十六进制>.zylc       # kind=2，加密的原图
      └─ t-<24 位随机十六进制>.zylc     # kind=0，加密的缩略图
```

- 加密文件的文件名是另取的随机十六进制串，不泄露原文件名、相簿或拍摄时间。它和 ZYLC 头里的 blobId 不是同一个值。
- 原图、缩略图和照片的对应关系只记在备份目录里；开了加密时备份目录本身也是加密的。
- 解密时核对 blob 的类型（kind）：原图、缩略图、目录、AI 整理结果各自只接受自己的 kind，拿缩略图冒充原图、拿别的文件冒充目录都会被拒绝。
- 网盘里出现过的 `index-broken-<时间>.json/.zylc` 是用户选“以这台手机为准重建”时另存的坏目录，不会被读取。

## 备份目录（index）

JSON 对象，流式读写（几万张照片也不会一次性占满内存）：

| 键 | 含义 |
| --- | --- |
| `v` | 格式版本，当前 2 |
| `seq` | 单调递增的序号。读到的比这台手机上次看到的小，说明网盘被还原过：这个账号暂停（不上传、不传目录，释放空间时也不算数），让用户选以哪边为准。目录损坏时同样暂停 |
| `items` | 每份备份一项：`r` 网盘文件 id、`e` 是否加密、`n` 文件名、`a` 相簿、`m` MIME、`t` 拍摄时间、`s` 大小、`h` 内容 SHA-256（`s` 对加密条目也是原文件的明文大小）、`th` 缩略图文件 id、`d` 上传它的设备、`k`（可选）加密用的不是当前这套密钥时，那套的 vaultId |
| `del` | 已删除的网盘文件 id（墓碑），别的手机合并时据此删掉对应记录 |
| `trash` | 等着从网盘删除、但还没删掉的文件 id；别的手机没在用它们时也会帮忙删 |
| `mode` | `{enc, at}`：这个账号最近一次的加密开关和改动时间。别的手机据此发现“另一台手机改了加密”，先不自动转换 |
| `settings` | 跟着账号走的设置（备份规则、相册设置），不含任何密钥 |

## 断点续传

8 MB 以上的文件用网盘的可续传上传会话。加密文件续传时，同一次运行内按内容指纹和密钥指纹复用同一组随机生成的
blobId、DEK 和 nonce（只在内存里），续传出来的密文和第一次上传的完全一样。内容或密钥变了标识就变；
会话失效、要从第 0 个字节重新开一个会话时，一律换一组新的随机数。所以不会出现同一组 nonce 加密两份不同内容。

## 加密开关不一致时

- 这个账号里还有加密条目、或者两台手机的加密开关不一致时，只要本机有密钥，目录照样加密上传（`index.zylc`），
  不把加密照片的文件名、相簿、时间写成明文。
- 没有密钥的手机只写明文目录，而且不写 `e = true` 的条目；它读不了 `index.zylc` 时会隔一段时间重新查一次密钥包，
  查到就提示解锁。
- 开着加密的手机不合并 `index.json`，也不删它，除非里面别的手机写的条目它全都认识（在加密目录、墓碑或待删除里）。

## 清理没人用的文件

- 每台手机在本机数据库里记一份上传日志：传之前记下文件名和开始时间，传完补上文件 id，写进记录后划掉。
- 定期对账时，只清理这份日志里、过了一天仍然没有任何记录或目录引用的文件（包括没等到上传结果、
  或 OneDrive 自动改名多出来的同名文件）。这个账号有目录没读到时先不清。
- 别的手机传的文件，这台手机从不当作孤儿删除。旧形式的文件（比如开启加密后的明文原图）由目录里的 `trash` 列表接力删除。
