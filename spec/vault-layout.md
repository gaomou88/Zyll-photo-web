# 网盘目录布局（v3）

0.1.7 起的布局。v2（下面附录）的文件都还认得，升级时自动整理过来。旧版 v1（用户可见的 `Zyll Vault/` 文件夹、HEAD 指针、操作日志）从未上线，已废弃。

```
<库根目录>                           # Google：appDataFolder（隐藏区），或开了分享功能后 My Drive 下的可见文件夹
                                    #   （带 appProperties.zyllRoot = "1"，名字按语言：Zyll 相册 / Zyll 相簿 / Zyll Photos / Zyll フォト）
                                    # OneDrive：/drive/special/approot（用户看到的是“应用/Zyll 相册”，名字是微软定的，改不了）
├─ storage.json                     # 存放位置标记（sharing.md 第 7 节），留在根目录：0.1.5、0.1.6 在这里找它
├─ 设置/                             # zyllDir = settings
│  ├─ keybundle.json                # 密钥包，见 keybundle.md
│  ├─ index.zylc                    # kind=3，加密的备份目录
│  ├─ index.json                    # 不加密时的备份目录（明文 JSON）
│  ├─ ai-results.zylc、identity.zylc、shared-albums.zylc、share-links.zylc、wiped.json
│  └─ index-broken-<时间>.zylc/.json # 用户选“以这台手机为准重建”时另存的坏目录，不会被读取
├─ 共享/                             # zyllDir = shared
│  ├─ <albumId>/                    # 共享相册，见 sharing.md 第 4 节
│  └─ 外链/<id>/                     # zyllDir = links，见 share-link.md
└─ 相册/                             # zyllDir = albums
   ├─ <32 位随机十六进制>.zylc        # kind=2，加密的原图
   ├─ t-<24 位随机十六进制>.zylc      # kind=0，加密的缩略图
   ├─ <相簿名>/<文件名>               # 不加密时的原图
   └─ .thumbs/<24 位随机十六进制>.jpg  # 不加密时的网盘缩略图
```

## 文件夹名和语言

| 文件夹 | 简中 | 繁中 | 英文 | 日文 | Google 标记 `appProperties.zyllDir` |
| --- | --- | --- | --- | --- | --- |
| 设置 | 设置 | 設定 | Settings | 設定 | `settings` |
| 共享 | 共享 | 共享 | Shared | 共有 | `shared` |
| 相册 | 相册 | 相簿 | Albums | アルバム | `albums` |
| 外链（在共享里） | 外链 | 外部連結 | Links | リンク | `links` |

- 名字只是给人看的（防止用户看不懂删掉）。程序不靠名字认：Google 按 `zyllDir` 标记找；OneDrive 没有自定义属性，上表里任何一种名字都认。
  同一种文件夹有几个时（两台设备同时建、OneDrive 上两种语言的名字）用最早建的那个，别的由整理步骤把内容并过去。
- 新建时按 App（网页版按浏览器）当前语言取名。App 第一次整理时、以及这台设备换了语言后，把这几个文件夹（Google 可见文件夹也算）改成当前语言的名字；
  只在“这台设备的语言变了”时改，两台语言不同的设备不会来回改。网页版不改名。
- 程序内部仍然用 v2 的“逻辑路径”（`vault/keybundle.json`、`共享/<albumId>`、`<相簿>/<文件>`…），由网盘接口换成实际位置：

| 逻辑路径 | 实际位置 |
| --- | --- |
| `vault/<固定文件>`（上面“设置”里列的）、`index.json`、`index-broken-*` | `设置/<文件名>` |
| `vault/<其他>`（原图、缩略图） | `相册/<文件名>` |
| `.thumbs/…`、`<相簿>/<文件>`（不加密） | `相册/…` |
| `共享/links/…` | `共享/外链/…` |
| `共享/<albumId>/…` | `共享/<albumId>/…` |
| `storage.json` | 根目录 |

  不加密时相簿名恰好是 `vault`、`共享`、`.thumbs` 的，前面加 `_`。

## 从 v2 升级（整理）

只移动和改名，不复制、不重新上传：Google 和 OneDrive 移动后文件 id 不变，备份目录、共享记录、外链都不用改，也不多占空间。

1. 第一次要用某个文件夹时“认领”v2 的旧文件夹：`vault/` 整个改名成“相册”（几万个文件一次搞定），`共享/` 改名打标记成“共享”，`共享/links/` 成“外链”。
2. App 每轮备份前在锁里整理（`LayoutTidy`）：根目录下的 `index.json`、`.thumbs/`、不加密时的相簿文件夹挪进“相册”或“设置”；“相册”里的固定文件挪进“设置”；
   重复的顶层文件夹并进正式的那个；空了的旧文件夹删掉（删之前再列一次，确认是空的）。第一次、没整理完的隔半小时再试，之后每 6 小时看一眼根目录，每天查一遍“相册”。
3. 整理到一半也能正常用：按逻辑路径找文件时先找新位置，找不到再找旧位置（固定文件还会找已经改名成“相册”的旧 vault 里）。写文件一律写到新位置。
4. 旧版 App（0.1.6 及以前）还会往旧位置写（Google 按缓存的文件夹 id，写进的是改了名的“相册”；OneDrive 按路径，会重新建出 `vault/`、`共享/`）：
   - 照片、缩略图、共享相册、外链：下次整理时挪进新位置；
   - 备份目录：读目录时当成多一份合并（不参与防回滚），新目录写好后删掉；旧版设备下次又写的话再合并一次，所以那台设备新备份的照片不会丢；
   - 密钥包：同一个库的留 `rev` 大的；不是同一个库就不动；身份密钥内容不一样时不删，挪进“相册”放着；已清空标记留新的；共享相册列表、外链列表、AI 整理结果用“设置”里那份（旧版设备本机还有，更新后会合并上来）。
   - 旧版设备在更新之前看不到别的设备新传的照片。这一点 App 更新说明里要写：所有设备都尽快更新。

## 上传时间（“最近添加”）

备份目录的每一项可以带 `u`：这个文件上传到网盘的时间（毫秒）。“最近添加”就是网盘里的全部照片（不管本机还有没有），按 `u` 从新到旧排，没有 `u` 的排在最后、按拍摄时间。

- 自己传的记传完的时间；换成新文件（转换加密、改信息重传、搬存放位置换了 id）沿用旧文件的时间，不算新添加。
- 别的设备传的取目录里的 `u`；目录里没有（旧版本传的）就用网盘上的文件创建时间补上，补上的写回目录，别的设备和网页版不用再补。
- 读到不是数字的 `u` 当没有，不算目录损坏。旧版本重写目录时会丢掉 `u`，新版本读到后各自保留本机知道的、下次写目录时补回去。

## 备份目录（index）

JSON 对象，流式读写（几万张照片也不会一次性占满内存）：

| 键 | 含义 |
| --- | --- |
| `v` | 格式版本，当前 2 |
| `seq` | 单调递增的序号。读到的比这台手机上次看到的小，说明网盘被还原过：这个账号暂停（不上传、不传目录，释放空间时也不算数），让用户选以哪边为准。目录损坏时同样暂停 |
| `items` | 每份备份一项：`r` 网盘文件 id、`e` 是否加密、`n` 文件名、`a` 相簿、`m` MIME、`t` 拍摄时间、`s` 大小、`h` 内容 SHA-256（`s` 对加密条目也是原文件的明文大小）、`th` 缩略图文件 id、`d` 上传它的设备、`k`（可选）加密用的不是当前这套密钥时，那套的 vaultId、`mo`（可选，只写 `true`）动态照片：文件里嵌着一段短视频，见 motion-photo.md、`u`（可选）上传到网盘的时间（毫秒），见上面“上传时间” |
| `del` | 已删除的网盘文件 id（墓碑），别的手机合并时据此删掉对应记录 |
| `trash` | 等着从网盘删除、但还没删掉的文件 id；别的手机没在用它们时也会帮忙删 |
| `mv` | （可选）搬存放位置时换过的文件 id：`[{o: 旧 id, n: 新 id, at: 搬的时间}]`，保留 90 天。读目录时先把 `items`、`del`、`trash` 和本机记录里的旧 id 换成新的，再合并；写目录时把本机知道的整张表原样带上（合并各份的，过期的去掉）。见 sharing.md 第 7 节 |
| `mode` | `{enc, at}`：这个账号最近一次的加密开关和改动时间。别的手机据此发现“另一台手机改了加密”，先不自动转换 |
| `settings` | 跟着账号走的设置（备份规则、相册设置），不含任何密钥 |

## 断点续传

8 MB 以上的文件用网盘的可续传上传会话。加密文件续传时，同一次运行内按内容指纹和密钥指纹复用同一组随机生成的
blobId、DEK 和 nonce（只在内存里），续传出来的密文和第一次上传的完全一样。内容或密钥变了标识就变；
会话失效、要从第 0 个字节重新开一个会话时，一律换一组新的随机数。所以不会出现同一组 nonce 加密两份不同内容。

## 加密开关不一致时

- 这个账号里还有加密条目、或者两台手机的加密开关不一致时，只要本机有密钥，目录照样加密上传（`index.zylc`），
  不把加密照片的文件名、相簿、时间写成明文。
- 没有密钥的手机只写明文目录，而且不写 `e = true` 的条目；它读不了 `index.zylc` 时会隔一段时间重新查一次密钥包，
  查到就提示解锁。
- 开着加密的手机不合并 `index.json`，也不删它，除非里面别的手机写的条目它全都认识（在加密目录、墓碑或待删除里）。

## 清理没人用的文件

- 每台手机在本机数据库里记一份上传日志：传之前记下文件名和开始时间，传完补上文件 id，写进记录后划掉。
- 定期对账时，只清理这份日志里、过了一天仍然没有任何记录或目录引用的文件（包括没等到上传结果、
  或 OneDrive 自动改名多出来的同名文件）。这个账号有目录没读到时先不清。
- 别的手机传的文件，这台手机从不当作孤儿删除。旧形式的文件（比如开启加密后的明文原图）由目录里的 `trash` 列表接力删除。
